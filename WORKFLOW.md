# Factuurscan - invoice-to-contract prototype

## Delivered and validated
- Local-first Python extraction on the three provided PDFs with page/evidence references, SHA-256 and explicit review status. 13 pages use embedded text; 3 supplier images were OCR-read locally and visually reviewed.
- Decimal price engine handles identical 365-day horizon, consumption/injection bands, supplier fixed costs, rebates, other supplier costs and unchanged network/tax assumption. Variable scenarios require a forecast basis. It reports separate supplier and total-bill percentages.
- Private owner-only `/atelier` shows real extracted amounts without customer identifiers and a non-sending comparison simulator. `/beheer` adds workflow, task and archive views.
- D1 persistent proposal gates, versions, action leases, consent-aware follow-up, audit records and protected signing artifacts. New migrations are additive; existing migration preserved.
- PandaDoc HMAC webhook verifies raw payload and provider completion status, matches signer email, archives unmodified protected PDF and provider evidence, hashes them, cancels outstanding follow-ups, then queues independent backup. Supplier submission only queued after backup receipt.
- Standard-library Python dispatcher (no OpenAI key required) prepares approved PandaDoc template documents, sends a proposal via PandaDoc, dispatches a configured voice bridge, requests independent backup and forwards to supplier bridge. No real credentials have been provided; dispatch defaults off.

## What is not running
No live PandaDoc account, OCR API, AI platform, email ingestion account, voice bridge, independent backup provider or OCTA+ partner portal/API. No customer was emailed, called, signed or enrolled. Python must run externally, with dependencies and durable private disk; Sites hosts React/TypeScript, not Python processes. Treat all gates as checks against actual supplier/current-tariff documents, not operator assertions to bypass controls.

## Endpoint contract
`POST /api/platform/inbound`: private bearer, multipart same as upload, X-Submission-ID UUIDv4 and `X-Mail-Authentication: validated`. Mail adapter must validate authenticated mailbox and explicit analysis request. It supplies verified contact/company context or routes missing fields for confirmation. No implicit AI call, WhatsApp or marketing permission is created. Privacy notice in email acknowledgement is still required. No mailbox polling/provider webhook has been activated.
`POST /api/platform/workflow` event prepare: requestId, proposal, gates. All gates listed in lib/workflow.ts true; fresh verified better annual result required. Proposal includes complete supplier/product/basis/source/validUntil/marketCoverage, authorized signerEmail, templateId, signerRole, exact template tokens and SHA-256 of contract and terms. A new version cannot overwrite existing signing/signature. Need revoke/reissue workflow before changing a sent contract.
`GET /api/platform/actions`: atomically leases one action for 120sec. Idempotency required; action id = kind/request/version. 5 max attempts. Follow-up planned +25minutes from provider-accepted sending, not from upload or report creation. Only weekdays 09-17 Brussels, opted-in, unpaused and unsigned. Outside window waits until allowed; a guaranteed max30-min call at night/weekend is not promised.
`POST /api/platform/actions`: id,leaseToken,result. Create requires documentId; send requires accepted+providerMessageId; voice requires callId; backup requires backupReceipt; supplier requires supplierReceipt. Dispatch and call completion are distinct; callId is provider acceptance, not evidence of a completed conversation. An authenticated platform may return failure for needs_review.
`GET /api/platform/workflow?id=UUID`: authenticated pre-dial stop check. Voice bridge must also implement stop checks/cancellation when signature or objection arrives during provider queueing. A race between dispatch and signature is still possible without provider-side cancellation.
`POST /api/pandadoc/webhook?signature=...`: receives PandaDoc HMAC signature as per official docs. Events handled only for document_completed_pdf_ready. Sites-private boundary requires an external public bridge to authenticate and forward the EXACT original body to the private site with its service header; preserve signature bytes. Do not make admin routes public to expose webhook. Implement forwarding on your existing Python/API infrastructure before subscribing.
`GET /api/platform/evidence?id=...`: manifest; artifact query downloads private PDF/provider JSON. Backup/supplier bridges obtain authorized file bytes, verify SHA-256 and preserve unmodified signed PDFs. Merely storing a manifest is not proof of file backup; backup bridge must actually copy and verify every byte on separate storage before backupReceipt. Supplier bridge must actually submit via the permitted partner interface and return durable receipt; no OCTA+ public submission API was verified.
